### Identificación de entidades

#### 1. USER (Usuario)
**Propósito**: Almacena información de todos los usuarios del sistema (estudiantes, profesores, administradores)

**Atributos principales**:
- `id`: Identificador único (Primary Key)
- `name`: Nombre completo del usuario
- `email`: Correo electrónico (único)
- `password`: Contraseña encriptada
- `role`: Rol del usuario (student, teacher, admin)
- `studentId`: ID del estudiante (opcional)
- `faculty`: Facultad a la que pertenece

#### 2. COURSE (Curso)
**Propósito**: Gestiona la información de los cursos académicos

**Atributos principales**:
- `id`: Identificador único (Primary Key)
- `name`: Nombre del curso
- `code`: Código único del curso
- `description`: Descripción del curso
- `schedule`: Horario del curso
- `classroom`: Aula asignada
- `teacherId`: ID del profesor responsable (Foreign Key)

#### 3. ACCOMMODATION (Acomodación/Solicitud)
**Propósito**: Registra las solicitudes de acomodación de los estudiantes

**Atributos principales**:
- `id`: Identificador único (Primary Key)
- `type`: Tipo de solicitud (exam_date_change, classroom_change, etc.)
- `status`: Estado de la solicitud (pending, approved, rejected)
- `description`: Descripción de la solicitud
- `motivo`: Motivo de la solicitud
- `requestedDate`: Fecha de la solicitud
- `newDate`: Nueva fecha propuesta
- `fechaOriginal`: Fecha original del evento
- `fechaPropuesta`: Fecha propuesta por el estudiante
- `newClassroom`: Nueva aula propuesta
- `extensionDays`: Días de extensión solicitados
- `teacherResponse`: Respuesta del profesor
- `studentId`: ID del estudiante (Foreign Key)
- `courseId`: ID del curso (Foreign Key)
- `teacherId`: ID del profesor (Foreign Key)

#### 4. ABSENCE (Falta)
**Propósito**: Registra las faltas de los estudiantes

**Atributos principales**:
- `id`: Identificador único (Primary Key)
- `fecha`: Fecha de la falta
- `materia`: Materia/curso donde ocurrió la falta
- `motivo`: Motivo de la falta
- `tipo`: Tipo de falta (justificada, injustificada, prevista)
- `observaciones`: Observaciones adicionales
- `studentId`: ID del estudiante (Foreign Key)
- `courseId`: ID del curso (Foreign Key)
- `teacherId`: ID del profesor (Foreign Key)

### Definición de atributos

#### Tipos de datos utilizados:
- **INTEGER**: Para identificadores y números enteros
- **STRING**: Para texto de longitud fija
- **TEXT**: Para texto de longitud variable
- **DATE**: Para fechas
- **ENUM**: Para valores predefinidos
- **BOOLEAN**: Para valores verdadero/falso

#### Restricciones de integridad:
- **NOT NULL**: Campos obligatorios
- **UNIQUE**: Valores únicos (email, studentId, course code)
- **DEFAULT**: Valores por defecto
- **CHECK**: Validaciones específicas

### Relaciones entre entidades

#### 1. USER ↔ COURSE (1:N)
- Un profesor puede tener múltiples cursos
- Un curso pertenece a un solo profesor
- **Relación**: `User.hasMany(Course)` / `Course.belongsTo(User)`

#### 2. USER ↔ ACCOMMODATION (1:N)
- Un estudiante puede hacer múltiples solicitudes
- Un profesor puede recibir múltiples solicitudes
- **Relación**: `User.hasMany(Accommodation)` (como student y teacher)

#### 3. COURSE ↔ ACCOMMODATION (1:N)
- Un curso puede tener múltiples solicitudes
- Una solicitud pertenece a un curso específico
- **Relación**: `Course.hasMany(Accommodation)` / `Accommodation.belongsTo(Course)`

#### 4. USER ↔ ABSENCE (1:N)
- Un estudiante puede tener múltiples faltas
- Un profesor puede registrar múltiples faltas
- **Relación**: `User.hasMany(Absence)` (como student y teacher)

#### 5. COURSE ↔ ABSENCE (1:N)
- Un curso puede tener múltiples faltas registradas
- Una falta pertenece a un curso específico
- **Relación**: `Course.hasMany(Absence)` / `Absence.belongsTo(Course)`

## 3.5.2 Modelo lógico

### Normalización de la base de datos

#### Primera Forma Normal (1NF)
- Todos los atributos contienen valores atómicos
- No hay grupos repetitivos
- Cada tabla tiene una clave primaria única

#### Segunda Forma Normal (2NF)
- Cumple con 1NF
- Todos los atributos no clave dependen completamente de la clave primaria
- Eliminación de dependencias parciales

#### Tercera Forma Normal (3NF)
- Cumple con 2NF
- No hay dependencias transitivas
- Todos los atributos no clave dependen directamente de la clave primaria

### Tablas y campos

#### Tabla: Users
```sql
CREATE TABLE Users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    role ENUM('student', 'teacher', 'admin') NOT NULL,
    studentId VARCHAR(50) UNIQUE,
    faculty VARCHAR(100),
    createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    updatedAt DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### Tabla: Courses
```sql
CREATE TABLE Courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) NOT NULL,
    code VARCHAR(50) UNIQUE NOT NULL,
    description TEXT,
    schedule VARCHAR(100) NOT NULL,
    classroom VARCHAR(50) NOT NULL,
    teacherId INTEGER NOT NULL,
    createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    updatedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (teacherId) REFERENCES Users(id)
);
```

#### Tabla: Accommodations
```sql
CREATE TABLE Accommodations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    type ENUM(
        'exam_date_change',
        'classroom_change',
        'notes_request',
        'assignment_extension',
        'deadline_extension',
        'exam_change',
        'absence_notification'
    ) NOT NULL,
    status ENUM('pending', 'approved', 'rejected') DEFAULT 'pending',
    description TEXT NOT NULL,
    motivo TEXT,
    requestedDate DATETIME NOT NULL,
    newDate DATETIME,
    fechaOriginal DATETIME,
    fechaPropuesta DATETIME,
    newClassroom VARCHAR(50),
    extensionDays INTEGER,
    teacherResponse TEXT,
    studentId INTEGER NOT NULL,
    courseId INTEGER NOT NULL,
    teacherId INTEGER NOT NULL,
    createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    updatedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (studentId) REFERENCES Users(id),
    FOREIGN KEY (courseId) REFERENCES Courses(id),
    FOREIGN KEY (teacherId) REFERENCES Users(id)
);
```

#### Tabla: Absences
```sql
CREATE TABLE Absences (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    fecha DATETIME NOT NULL,
    materia VARCHAR(255) NOT NULL,
    motivo TEXT,
    tipo ENUM('justificada', 'injustificada', 'prevista') DEFAULT 'injustificada',
    observaciones TEXT,
    studentId INTEGER NOT NULL,
    courseId INTEGER NOT NULL,
    teacherId INTEGER NOT NULL,
    createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    updatedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (studentId) REFERENCES Users(id),
    FOREIGN KEY (courseId) REFERENCES Courses(id),
    FOREIGN KEY (teacherId) REFERENCES Users(id)
);
```

### Claves primarias y foráneas

#### Claves Primarias (Primary Keys)
- **Users.id**: Identificador único de usuario
- **Courses.id**: Identificador único de curso
- **Accommodations.id**: Identificador único de solicitud
- **Absences.id**: Identificador único de falta

#### Claves Foráneas (Foreign Keys)
- **Courses.teacherId** → **Users.id**: Profesor responsable del curso
- **Accommodations.studentId** → **Users.id**: Estudiante que hace la solicitud
- **Accommodations.courseId** → **Courses.id**: Curso relacionado con la solicitud
- **Accommodations.teacherId** → **Users.id**: Profesor que recibe la solicitud
- **Absences.studentId** → **Users.id**: Estudiante con la falta
- **Absences.courseId** → **Courses.id**: Curso donde ocurrió la falta
- **Absences.teacherId** → **Users.id**: Profesor que registra la falta

### Procedimientos almacenados

#### Función para estadísticas de solicitudes
```sql
CREATE FUNCTION get_accommodation_stats(student_id INTEGER)
RETURNS TABLE (
    total_requests INTEGER,
    approved_requests INTEGER,
    pending_requests INTEGER,
    rejected_requests INTEGER
) AS $$
BEGIN
    RETURN QUERY
    SELECT 
        COUNT(*) as total_requests,
        COUNT(CASE WHEN status = 'approved' THEN 1 END) as approved_requests,
        COUNT(CASE WHEN status = 'pending' THEN 1 END) as pending_requests,
        COUNT(CASE WHEN status = 'rejected' THEN 1 END) as rejected_requests
    FROM Accommodations 
    WHERE studentId = student_id;
END;
$$ LANGUAGE plpgsql;
```

### Triggers y funciones

#### Trigger para actualizar timestamps
```sql
CREATE TRIGGER update_user_timestamp
    AFTER UPDATE ON Users
    FOR EACH ROW
    BEGIN
        UPDATE Users SET updatedAt = CURRENT_TIMESTAMP WHERE id = NEW.id;
    END;
```

#### Función para notificaciones automáticas
```sql
CREATE FUNCTION notify_accommodation_status_change()
RETURNS TRIGGER AS $$
BEGIN
    -- Lógica para enviar notificaciones cuando cambia el estado
    IF OLD.status != NEW.status THEN
        -- Insertar en tabla de notificaciones
        INSERT INTO Notifications (userId, message, type, createdAt)
        VALUES (NEW.studentId, 
                'Su solicitud ha sido ' || NEW.status,
                'accommodation_status',
                CURRENT_TIMESTAMP);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER accommodation_status_notification
    AFTER UPDATE ON Accommodations
    FOR EACH ROW
    EXECUTE FUNCTION notify_accommodation_status_change();
```

### Definición de campos

#### Campos de auditoría
Todos los modelos incluyen campos de auditoría estándar:
- **createdAt**: Fecha y hora de creación del registro
- **updatedAt**: Fecha y hora de la última actualización

#### Campos de relación
- **Foreign Keys**: Mantienen la integridad referencial entre tablas
- **Cascade Rules**: Define el comportamiento al eliminar registros relacionados
- **Indexes**: Optimizan las consultas frecuentes

### Dominios y restricciones

#### Dominios de datos
```sql

CREATE DOMAIN user_role AS ENUM('student', 'teacher', 'admin');

CREATE DOMAIN accommodation_status AS ENUM('pending', 'approved', 'rejected');
```

#### Restricciones de negocio
```sql
-- Restricción: Un estudiante no puede tener más de 3 solicitudes pendientes
ALTER TABLE Accommodations ADD CONSTRAINT chk_max_pending_requests
    CHECK (
        (SELECT COUNT(*) FROM Accommodations 
         WHERE studentId = studentId AND status = 'pending') <= 3
    );

-- Restricción: Las fechas propuestas deben ser futuras
ALTER TABLE Accommodations ADD CONSTRAINT chk_future_dates
    CHECK (fechaPropuesta > CURRENT_TIMESTAMP);

-- Restricción: Los días de extensión deben ser positivos
ALTER TABLE Accommodations ADD CONSTRAINT chk_positive_extension
    CHECK (extensionDays > 0);
```

#### Dependencias de integridad referencial
- **Courses.teacherId** depende de **Users.id**
- **Accommodations.studentId** depende de **Users.id**
- **Accommodations.courseId** depende de **Courses.id**
- **Accommodations.teacherId** depende de **Users.id**
- **Absences.studentId** depende de **Users.id**
- **Absences.courseId** depende de **Courses.id**
- **Absences.teacherId** depende de **Users.id**

#### Reglas de cascada
```sql
-- Al eliminar un usuario, eliminar sus cursos
ALTER TABLE Courses ADD CONSTRAINT fk_courses_teacher
    FOREIGN KEY (teacherId) REFERENCES Users(id) ON DELETE CASCADE;

-- Al eliminar un curso, eliminar sus solicitudes y faltas
ALTER TABLE Accommodations ADD CONSTRAINT fk_accommodations_course
    FOREIGN KEY (courseId) REFERENCES Courses(id) ON DELETE CASCADE;

ALTER TABLE Absences ADD CONSTRAINT fk_absences_course
    FOREIGN KEY (courseId) REFERENCES Courses(id) ON DELETE CASCADE;
```
