# 3.3 MAPA DE NAVEGACIÓN O ARQUITECTURA DE INFORMACIÓN DE LA APLICACIÓN WEB

## 3.3.1 Arquitectura de información

### Jerarquía de contenidos

La aplicación web del Sistema de Solicitudes Académicas está organizada en una estructura jerárquica que refleja los diferentes roles de usuario y sus necesidades específicas:

#### Nivel 1: Páginas principales por rol
- **Estudiante**: Dashboard, Solicitudes, Faltas, Mis Solicitudes
- **Profesor**: Dashboard, Solicitudes, Faltas, Administración
- **Administrador**: Dashboard, Solicitudes, Faltas, Panel de Administración

#### Nivel 2: Funcionalidades específicas
- **Gestión de Solicitudes**: Crear, ver, editar, aprobar/rechazar
- **Gestión de Faltas**: Registrar, consultar, justificar
- **Administración**: Gestión de usuarios, cursos, reportes

### Categorización de funcionalidades

#### Funcionalidades por tipo de usuario:

**Estudiantes:**
- Visualización de dashboard personalizado
- Creación de solicitudes de acomodación
- Consulta de faltas y justificaciones
- Seguimiento de solicitudes propias

**Profesores:**
- Gestión de solicitudes de sus cursos
- Registro y consulta de faltas de estudiantes
- Administración de cursos asignados
- Respuesta a solicitudes de estudiantes

**Administradores:**
- Gestión completa del sistema
- Administración de usuarios y roles
- Gestión de cursos y asignaciones
- Reportes y estadísticas del sistema

### Flujo de información

El flujo de información sigue un patrón de entrada-salida donde:

1. **Entrada**: Los usuarios ingresan datos a través de formularios específicos
2. **Procesamiento**: El sistema valida, almacena y procesa la información
3. **Salida**: Los datos se presentan en dashboards y reportes personalizados
4. **Retroalimentación**: Notificaciones y actualizaciones de estado en tiempo real

## 3.3.2 Estructura de navegación

### Menú principal

El menú principal está implementado en el componente `Navbar.js` y se adapta dinámicamente según el rol del usuario:

```javascript
// Estructura base del menú
const baseItems = [
  { name: 'Inicio', href: '/dashboard' },
  { name: 'Solicitudes', href: '/solicitudes' },
  { name: 'Faltas', href: '/faltas' },
];
```

### Submenús y categorías

#### Para Estudiantes:
- **Inicio**: Dashboard personalizado con resumen de solicitudes
- **Solicitudes**: Gestión de solicitudes de acomodación
- **Faltas**: Consulta de faltas registradas
- **Mis Solicitudes**: Seguimiento de solicitudes propias

#### Para Profesores:
- **Inicio**: Dashboard con solicitudes pendientes
- **Solicitudes**: Gestión de solicitudes de estudiantes
- **Faltas**: Registro y consulta de faltas
- **Administración**: Gestión de cursos asignados

#### Para Administradores:
- **Inicio**: Dashboard administrativo
- **Solicitudes**: Gestión global de solicitudes
- **Faltas**: Administración de faltas del sistema
- **Administración**: Panel completo de administración

### Rutas de navegación (breadcrumbs)

El sistema implementa navegación jerárquica con las siguientes rutas principales:

```
/ (raíz)
├── /login (autenticación)
├── /register (registro)
├── /dashboard (página principal)
├── /solicitudes (gestión de solicitudes)
├── /faltas (gestión de faltas)
├── /mis-solicitudes (solicitudes del estudiante)
└── /admin (panel administrativo)
```

### Enlaces internos

El sistema utiliza React Router para la navegación interna, con rutas protegidas que requieren autenticación:

```javascript
// Rutas protegidas
<PrivateRoute>
  <Dashboard />
</PrivateRoute>
```

## 3.3.3 Mapa del sitio

### Diagrama de estructura del sitio

```
Sistema de Solicitudes Académicas
├── Autenticación
│   ├── Login (/login)
│   └── Registro (/register)
├── Dashboard Principal (/dashboard)
├── Gestión de Solicitudes (/solicitudes)
├── Gestión de Faltas (/faltas)
├── Solicitudes del Estudiante (/mis-solicitudes)
└── Panel Administrativo (/admin)
```

### Páginas principales

1. **Login** (`/login`): Punto de entrada al sistema
2. **Dashboard** (`/dashboard`): Página principal personalizada por rol
3. **Solicitudes** (`/solicitudes`): Gestión de solicitudes de acomodación
4. **Faltas** (`/faltas`): Gestión de faltas y justificaciones
5. **Mis Solicitudes** (`/mis-solicitudes`): Vista del estudiante de sus solicitudes
6. **Admin** (`/admin`): Panel administrativo

### Páginas secundarias

- **Perfil de Usuario**: Gestión de datos personales
- **Configuración**: Ajustes del sistema
- **Reportes**: Generación de reportes y estadísticas

### Páginas especiales

- **Error 404**: Página no encontrada
- **Error 500**: Error interno del servidor
- **Mantenimiento**: Página de mantenimiento del sistema

## 3.3.4 Flujos de usuario

### Casos de uso principales

#### 1. Flujo de Autenticación
```
Usuario no autenticado → Login → Validación → Dashboard
```

#### 2. Flujo de Solicitud de Acomodación (Estudiante)
```
Dashboard → Solicitudes → Nueva Solicitud → Formulario → Envío → Confirmación
```

#### 3. Flujo de Gestión de Solicitudes (Profesor)
```
Dashboard → Solicitudes → Revisar Solicitud → Aprobar/Rechazar → Notificación
```

#### 4. Flujo de Administración (Admin)
```
Dashboard → Administración → Gestión de Usuarios/Cursos → Configuración
```

### Rutas de navegación típicas

#### Estudiante:
1. Login → Dashboard → Ver solicitudes pendientes
2. Dashboard → Nueva solicitud → Completar formulario → Enviar
3. Dashboard → Mis solicitudes → Ver estado → Seguimiento

#### Profesor:
1. Login → Dashboard → Revisar solicitudes pendientes
2. Dashboard → Solicitudes → Aprobar/Rechazar → Comentar
3. Dashboard → Faltas → Registrar falta → Justificar

#### Administrador:
1. Login → Dashboard → Ver estadísticas generales
2. Dashboard → Administración → Gestionar usuarios
3. Dashboard → Reportes → Generar estadísticas

### Puntos de entrada y salida

#### Puntos de entrada:
- **Login**: Acceso principal al sistema
- **Registro**: Creación de nuevas cuentas
- **Recuperación de contraseña**: Recuperación de acceso

#### Puntos de salida:
- **Logout**: Cierre de sesión seguro
- **Timeout de sesión**: Cierre automático por inactividad
- **Navegación externa**: Enlaces a sistemas externos

## Consideraciones de Usabilidad

### Principios de diseño aplicados:

1. **Consistencia**: Navegación uniforme en todas las páginas
2. **Eficiencia**: Acceso rápido a funcionalidades principales
3. **Claridad**: Menús intuitivos y descriptivos
4. **Accesibilidad**: Navegación compatible con lectores de pantalla
5. **Responsividad**: Adaptación a diferentes dispositivos

### Mejoras implementadas:

- Navegación adaptativa según rol de usuario
- Breadcrumbs para orientación del usuario
- Menús colapsables en dispositivos móviles
- Indicadores visuales de estado de solicitudes
- Notificaciones en tiempo real de cambios de estado
